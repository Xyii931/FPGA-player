# 基于安路 HX4S20C 的 HDMI 多媒体播放系统

| 项目 | 内容 |
|---|---|
| 版本 | v0.4，2026-10-18 统一修订 |
| 状态 | 方案基线，待实现与实测 |
| 平台 | HX4S20C，EG4S20BG256 |
| 定位 | 具备图音联动、现场配置和应急插播的嵌入式数字标牌播放机 |

本方案保留功能丰富、创新有效的方向，以 FAT32 素材管理、播放时间线、图像合成和真实音轨播放形成整体设计。设计目标与完成状态必须分开；首帧时间、读卡速度、资源占用等以测试记录为准。

## 1. 赛题与产品目标

### 1.1 基础要求

| 编号 | 要求 |
|---|---|
| B1 | 本地存储自动扫描、识别、装载至少 4 幅 640×480、24-bit 图片 |
| B2 | FPGA 缓存管理和连续稳定 HDMI 显示，无明显撕裂、持续花屏或卡死 |
| B3 | 至少两个按键，分别支持下一张和自动轮播启停；轮播周期可配置 |
| B4 | 显图同时输出 HDMI 可识别音频，链路稳定 |

指南另要求：“提交作品中的整体实现架构、音频和图片处理方法不能和参考实例相同。”本方案通过文件系统、独立播放调度、多槽缓存、图像处理和文件音频体现差异。底层加密 IP 拟复用，不能把复用边界、评分或参赛资格解释为赛方已经确认的结论；提交前核实规则。

## 2. 硬件基线与范围

| 项目 | 当前依据与处理 |
|---|---|
| LUT / FF | 赛题指南及当前 TD 目标库容量均为各 19600 |
| SDRAM | 指南及参考原语：器件集成 2M×32 bit，即 8 MiB；不称独立外置芯片 |
| 块 RAM | 当前 TD 目标库报告 BRAM9K 64 个、BRAM32K 16 个；与手册 `BRAMb:1008K` 的口径差异仍待核对。按块类型分别检查容量，不能用有效数据字节小计代替映射结果 |
| DSP | 当前 TD 目标库报告 29 个；已有 OSD 模块映射使用 6 个，图像及整机乘法仍须核对实际占用 |
| PLL | 指南 4 个；本方案使用两个 PLL，音频由像素域使能节拍驱动 |
| 时钟 | 板载 50 MHz，R7；系统 100 MHz、存储 125 MHz、视频 25 MHz、串行器 125 MHz |
| Flash | W25Q64 为素材/设置；W25Q16 为配置启动，分别管理 |
| 外设 | TF SPI、HDMI B、USB-UART、四键四拨码；引脚表见 02 |

输出基线为 640×480、25 MHz 像素时钟、800×525 总时序，场频约 59.524 Hz。显示器支持 720p 的建议不等于播放器必须输出 720p。720p 实验需要重新核算视频时序、帧槽容量和带宽，不能只改输出分辨率参数。

**范围决定**：本项目不做动态视频、JPEG/MP3/AAC 解码、HDMI 输入、网络发布或外部 MCU 深度协处理。这是当前范围选择；不以缺乏测量的资源数字断言所有视频算法都无法实现。

## 3. 总体结构

```text
按键/拨码/编码器/红外/UART
             ↓
      事件队列与配置仲裁 ── 设置持久化
             ↓
      播放调度与应急状态机
        ├─ TF SPI → FAT32多文件上下文 → 素材索引/播放列表
        ├─ BMP → 缩放/旋转/版式写入 → SDRAM帧槽
        ├─ WAV/APT → 双音轨FIFO → 音量/交叉淡化/提示音
        └─ OSD文字/菜单/HUD

SDRAM → 双源行缓存 → 转场坐标/权重 → OSD → HDMI核 → HDMI B
双音轨FIFO → 48kHz像素域采样 → HDMI核音频口
```

控制模块发命令，数据模块返回完成/错误/水位事件。文件读取支持至少三个独立上下文：一条图片流和两条音频流；扇区读在物理通路上串行调度。音频紧急补给优先于图片后台装载。不能用单个全局文件指针交错读不同文件。

写路径完成常态缩放、旋转和版式；显示路径按行顺序从 SDRAM 预取，再在行缓存中执行横向转场映射。缩放转场按映射选择源行，见 04。该结构不会把“行内像素映射”误写成“SDRAM 每像素随机读取”。

## 4. 时钟、复位与跨域

具体频率、生成时钟和复位端口见 02 §2。

- 全局复位：上电、KEY1 长按 3 秒；允许 HDMI 重新锁定。
- 视频复位：全局复位或视频 PLL 失锁。
- 存储基础设施复位：全局复位或系统 PLL 失锁。
- 媒体软复位：仅重启读卡、文件解析、装载及播放上下文。先阻止新媒体请求并排空已提交事务，保持 SDRAM 控制器、前台帧、扫描和 HDMI 工作。

每个时钟域分别异步置位、同步释放。多位参数用稳定载荷握手/异步 FIFO；不能把每个位分别过两级触发器当成原子更新。像素域在帧边界一次锁存源槽、效果与参数。

系统 PLL 的 100/125 MHz 输出不默认声明异步；在 TD 中建立真实生成时钟并检查相位。不同 PLL 间按跨域接口处理。约束例外必须定位到已验证同步结构，不能通过大范围 false path 获得表面时序通过。

## 5. 存储与资源管理

### 5.1 SDRAM

六个固定帧槽沿用 640×480、每像素 32 bit，占 7372800 B；槽地址见 02 §3。槽角色动态分配，显示/转场源必须加读锁，不能同时被后台覆盖。预取帧就绪后通过指针交换提交，不复制整帧。

SLOT4 用于一页 3×3 缩略图，SLOT5 预留常驻告警；其他槽管理当前、下一帧和合成临时结果。多窗口若需要超过可用的原图槽，顺序重读 TF 并在离屏槽累积合成。原图没有全量常驻保证。

尾部空间预留文件/调试等用途；任何分配必须登记边界。RGBA 字序统一为 `{R,G,B,A}`；BMP 默认按不透明图片导入，保留 A 字节供内部图层使用。

### 5.2 BRAM 预算（未综合）

| 用途 | 计划有效数据容量 |
|---|---|
| 双源双缓冲行缓存 | 10 KiB |
| 双线性两行源缓存，最大宽 1920 | 15 KiB |
| 两音轨 FIFO，各 2048×48 bit | 合计 24 KiB |
| 400 个中文字模缓存 | 12.5 KiB |
| ASCII 96×16 B | 1.5 KiB |
| FAT/扇区/目录缓存 | 约 6 KiB |
| 像素、命令等其他 FIFO | 暂留 12 KiB |
| OSD 文本/属性、行掩码及参数 | 暂留 10 KiB |
| 双bank素材索引及三份排列（2026-10-25更新） | 22448 B，约21.92 KiB，含policy元数据 |
| 目录候选名称缓冲（2026-10-23新增） | 64 B；复用上述索引，不增加第二份索引 |
| 小计 | 约 113 KiB，尚未含 IP 内部与块映射碎片 |

上述 OSD 预算含文本/属性，APT 块重排另需约 2 KiB，可从其他 FIFO 预留中分配并记录。100 KiB 为自研部分的规划目标，不能据此承诺放得下。新增双bank索引后，当前规划已超目标约13 KiB，不能再引用旧91 KiB小计作为余量；须以TD实际映射重算，必要时将索引改用受管理外部存储或重新分配缓存。未因此自行删减功能，亦未确认目标器件可容纳。LUT 约 14850 的旧分项仅是粗估，新增多上下文、双音轨、合成与跨域可能改变它；HDMI/SDRAM IP 占用未知。P0 建立真实占用，之后每阶段重算。

2026-10-25块类型分配：索引的六份字符串RAM已在源码中显式选择32K块，目标为6/16个BRAM32K；21 KiB字符串有效数据对应24 KiB块容量，另计元数据、排列及控制。实际块数仍待重新综合，不能将旧40个BRAM9K报告直接换算为本版节省量。

两条1920×32-bit缩放行缓存和两路2048×48-bit音频FIFO也已在源码中显式选择32K块，目标分别4个和6个，连同索引的源码分配目标合计16/16个BRAM32K，尚未重新综合；该池按目标已无预留，实际映射多用一块也会超预算。音频只在`audio_frame_fifo`开启`async_fifo.USE_BRAM32K`，其他小控制/事件FIFO保留RTL推断，不削减双声道24bit精度或2048帧容量。三者合计16个是源码分配目标，不是现版映射结果。其他存储须落在64个BRAM9K及可承受的LUT/FF中；全工程实例数、物理宽深限制和映射碎片仍须逐项核对。100 KiB是规划目标，器件是否容纳按两类块分别计算，不以有效字节小计或单模块可容纳代替整机判断。

演示/恢复源的生成播放列表不再各存4096 B文本，改为各64×17bit配对记录，共272 B，按需生成完全相同的最多4096 B逻辑文件。两实例源码数据位比旧文本存储减少63360bit（7920 B），不作为实测RAM或逻辑节省。条目元数据现按每条四个32bit字存为每实例512×32同步RAM，单口分拍读取后再比较或发布，替代原五组数组的多路组合读取；元数据声明总位数不变，新增完整记录及流字段寄存器，不承诺实际块数或LUT/FF收益。512 B后端缓冲也改为单同步读口，表/载荷CRC和在线素材均先读再消费，固定头字段另有每实例最多34 B快照寄存器；背压保持读回值，短扇区尾部填0。按最大声明，两个源的条目元数据、后端缓冲和配对记录合计5392 B，头快照、控制/读寄存器另计；旧113 KiB表未单列这些源，不能从旧小计简单减去7920 B得到整机新预算。新增准备周期的吞吐、实际映射和全工程小块RAM余量仍须核查。

### 5.3 素材 Flash 与 TF

W25Q64 的唯一分区表见 02 §3.2，字库使用 94×94 槽表，设置区双备份。TF 目录、播放列表、文件上限见 02 §4。最大索引 64 项、路径最多 64 个 ASCII 字节；超出明确报告，不再声称“任意数量”。

FAT 损坏时可启用扇区扫描恢复，但只保证恢复**连续存放且可完整校验**的 BMP。碎片文件不能靠文件头恢复簇链；失败进入常驻安全页。

## 6. 输入格式

详细字节布局见 02 §4。图片支持未压缩 24/32-bit BMP、40 B DIB 头、1×1—1920×1080，正确处理正负高度和 4 B 行对齐。WAV 为 PCM16/48 kHz/双声道；APT 为自定义容器包裹 IMA ADPCM，不等同于 WAV 的 ADPCM 布局。

播放列表提供每项图片、音轨、标题、停留时长、效果与时长，以及全局缺省值和背景音轨bgm。不存在列表时扫描 `/PLAY/IMG`，再尝试根目录。先保证英文文件名和 GB2312 标题；UTF-8 导入放在 PC 转换工具，FPGA 不做通用编码转换。

## 7. 图像通路

### 7.1 装载与版式

BMP 解析 → 写路径缩放 → 旋转/布局坐标 → 离屏槽 → 帧边界提交。最近邻与双线性由菜单选择，不能在未告知用户时覆盖设置。双线性行缓存按最大输入宽设计；若超预算，缩小输入上限或降级最近邻并报告。

全屏、PiP（右上角）、左右双画面、四宫格和缩略图墙均预渲染到离屏槽。重绘期间继续显示旧帧，完成后转场提交；不允许故意插入一帧黑屏。九张缩略图只是一页，超过九项分页。

转 90°/270° 后再按宽高比适配：640×480 旋转为 480×640，再显示为 360×480，居中偏移 `(140,0)`。坐标公式见 04；不能用 480×360 代替旋转后的比例。

### 7.2 七种转场

淡入、滑入、推挤、斜向擦除、百叶窗、块状切换、中心缩放。滑入/推挤需要行内坐标平移，不能把单纯权重阈值叫作滑动。缩放需要映射源行与行内坐标。读侧映射契约见 04。

时长 200/400/600/1000 ms，默认 400 ms，按实际场频换算帧数。转场期间收到 NEXT/PREV 只更新一个待执行目标，当前转场完成后执行；无连续画面快照时不能直接替换当前混合源。

### 7.3 性能边界

25 MHz SPI 理论有效负载上限 3.125 MB/s；≥2.5 MB/s 是多块读目标。921654 B 的 BMP 在该速率下仅数据读取就约 0.369 s；1920×1080 RGB888 约 6.22 MB，约 2.49 s，未计碎片/解析等开销。

5—30 ms 只能作为**原图已经在 SDRAM 且访问有效**的合成估计，不能用于 TF 重载、九张原图生成或随机旋转写入的保证。125 MHz、32 bit 得到 500 MB/s 只是原始总线峰值，刷新、激活、读写切换及仲裁后持续带宽必须测出。

双源显示有效像素流量约 36.57 Mword/s，即 146.3 MB/s。行截止时间、最大连续阻塞、缓存水位比单一平均利用率更重要；以 07 的无欠载和截止时间验证为准。

## 8. 音频与图音同步

PCM16 满幅归一化为 PCM24 使用 `{sample16,8'b0}`。在像素域持续产生 48 kHz 样本节拍，所有音轨转换为相同的 24-bit 有符号格式后混合、饱和输出。

双音轨各 2048 帧 FIFO，每路约 42.67 ms；正常只播放一条，切图中点启动 200 ms 交叉淡化。两音轨必须预打开、预缓冲，不具备条件时继续旧画面并等待，不用静音掩盖装载未完成。无单项音轨时使用全局bgm，均未设置则对静音交叉淡化；同一bgm跨图连续播放，到结尾双上下文交叉淡化循环。提示音为独立 ROM 生成，混音预留余量并饱和。

音量 0—16，增益 `v/16`；静音精确置零但有效样本不断。欠载不读空 FIFO，输出从最后有效幅度在 64 个样本内降至零；补足水位后渐入恢复。暂停以淡出后的实际播放位置保存上下文，恢复重新预充，不能自然抽空 FIFO 后丢失位置。

ACR：`128×fs = f_TMDS×N/CTS`。本方案 RGB888 的 `f_TMDS=25 MHz`，N=6144、CTS=25000。125 MHz 是串行器的 5 倍工作时钟。参考源码按 48 个样本统计像素周期，与该值一致。P3 验证常量 CTS 与参考测量方式，不再以 125000 为默认或强制三档试错。

音画偏移统一定义 `Δ=t_audio_anchor−t_video_anchor`，范围 ±500 ms：正值音频晚，负值音频早。共同时间线安排两事件；手动切换遇负偏移时先起目标音频、后起画面，允许增加准备等待。FIFO 水位只用于供数，不用于计算媒体偏移。详见 05。

## 9. 操作与界面

### 9.1 输入

KEY1 短按上一张、长按 3 s 全局复位；KEY2 下一张；KEY3 自动轮播启停；KEY4 菜单/返回。菜单内复用上一项、下一项、确认、返回。组合键恢复出厂设置不再占用，统一通过菜单确认执行。

SW1 自动轮播、SW2 强制静音、SW3 PiP/FULL、SW4 内置演示。拨码仅在位置变化时产生配置事件，SW2/SW4 同时作为硬覆盖；UART、菜单、按键按事件顺序更新运行配置，具体优先级见 02。编码器与红外使用各自独立 GPIO，不能与调试 DAC 复用同一引脚同时工作。

### 9.2 OSD 与控制

菜单包括播放、显示、音频、系统、关于，具体参数与 UART 命令都见 02。支持中文菜单、提示条、字幕标题、缩略图选框与 HUD，以及亮度、对比度、饱和度调整和七效果随机选择。OSD 菜单/告警层在 HUD 之上；背景矩形可半透明，字形不做抗锯齿。

HUD 显示帧率、SD 读取速度、存储忙占比、视频/音频欠载和当前项。LUT/BRAM 占用来自构建报告写入的版本元数据，不是 FPGA 自动测出的动态值。内部计数只反映计划事件/缓冲延迟，不等于显示器扬声器端真实音画偏差。

参数默认只更新运行态，执行 SAVE/菜单“保存设置”才写 Flash；载入最新有效备份，失败用默认值。Flash 写期间不停止时钟域，冻结资源更新并使用已缓存字模。

| `fat32_core` / `media_indexer` | 多文件上下文、目录、素材及播放列表 |
| `flash_ctrl` / `settings_store` | Flash 事务、双备份参数 |
| `bmp_parser` / `image_scaler` | 图像解析与写路径缩放 |
| `audio_decoder` | 两上下文 PCM/APT 解码 |
| `sdram_arbiter` / `fb_writer` / `fb_reader` | 存储仲裁、合成写入、双源行预取 |
| `scanout_engine` / `blend_unit` | 显示时序、转场坐标权重、混合 |
| `osd_compositor` / `menu_engine` | 文字/图形合成与菜单 |
| `ui_core` / `telemetry_uart` | 输入、事件与串口协议 |
| `playlist_scheduler` / `watchdog` / `app_top` | 时间线、状态监督和连接 |

通用组件包括异步 FIFO、载荷握手、CRC、采样节拍、ACR 与音频混合。24 个主要模块不是对最终 RTL 文件数量的限制。端口契约见 02，编写 RTL 时需形成可编译声明并通过接口审查。

## 11. 资源与实现约束

P0 取得目标器件资源和 IP 占用；P1—P6 逐项记录 LUT/FF/BRAM 与布局布线时序。需要乘法的通路评估位宽、并行度和共享周期，不用“乘法一律移位加”掩盖动态系数的实现成本。

资源裁剪优先：可选频谱 → 红外 → 装饰动画/图标 → 双线性 → 四宫格。避免重复计算同一裁剪的节省量。保留合规基础、文件管理、真实图音联动、菜单和应急场景。是否削减既定功能由实际报告决定。

参考包中的负时序裕量是待调查线索，不能推断本机必然失败，也不能未经路径报告认定唯一原因。目标为所有需分析路径的 setup/hold 均通过；时钟覆盖率、约束例外与 IO 时序需审查。

## 12. 可靠性

- 看门狗默认 5 s，仅在存在未完成事务时监督对应进度；静态播放和暂停不应因“没有新文件事务”误复位。
- 卡每 500 ms 在安全命令边界探测；读失败可提前报告。无卡每 2 s 尝试重初始化；从成功重新初始化起，5 s 内恢复测试素材播放为目标，不能承诺所有大图都在该时间内。
- 掉卡先保持完整旧帧并叠加 NO CARD；无有效旧帧才显示常驻告警/安全页。HDMI 时序持续，音频淡出；重扫后按文件身份恢复，文件不存在则从首项开始。
- 坏 BMP、截断文件和解析失败不提交半帧；跳过并报告。FAT 簇链结合文件大小、卡容量、访问预算判断，发现环/越界终止。
- 媒体恢复连续失败三次进入安全模式，保留 UART 和卡重试。全局失锁与全局复位不承诺 HDMI 无中断。

## 13. 与参考工程的差异

| 维度 | 参考工程 | 本方案 |
|---|---|---|
| 素材定位 | 前 64 MiB 物理扇区识别 BMP | FAT32 路径、簇链与播放列表，有限恢复扫描 |
| 缓存 | 双缓冲 | 六槽角色/读锁、预取、合成、帧边界提交 |
| 图像 | 固定规格图片直出 | 写路径缩放/版式/旋转，双源行缓存转场 |
| 音频 | 内部测试音经 I2S 往返 | 文件解码、并行 PCM、双轨混合与时间线 |
| 交互 | 按键与原有状态显示 | 中文菜单、多输入配置、UART 协议、持久化 |
| 场景 | 图片与测试音演示 | 图音展陈、缩略图浏览、应急插播及恢复 |

底层 IP 复用、参考源码借鉴和新增模块分别登记，避免把已有机制列为原创。不能仅凭“BM”字节推断原工程必然误识别，它还有其他头部判据。

## 15. 实施顺序与出口

| 阶段 | 内容 | 核心出口 |
|---|---|---|
| P0 | 参考基线、资源、时钟复位、SDRAM 契约、彩条 | 资源已知、基础路径时序通过、可复现视频 |
| P1 | SD/FAT32、多上下文、目录与播放列表 | 字节正确、碎片可读、供数预算可测 |
| P2 | 缓存、缩放、版式、七种转场、旋转 | 像素正确、源槽不被覆盖、无行欠载 |
| P3 | WAV/APT、双轨、音量、ACR、同步 | 码值与音调正确、30 min 稳定、切换无爆音 |
| P4 | 菜单、中文、UART、配置保存、多输入 | 配置与协议统一、断电恢复、图层正确 |
| P5 | 故障恢复与长跑 | 受控故障可恢复、8 h 无卡死和累积欠载 |
| P6 | 应急插播、内置演示、可选外设 | 常驻告警≤200 ms、退出恢复播放、演示完整 |
| P7 | 文档、部署、镜像、视频与答辩 | 可独立重建、固化启动、记录完整 |

P0→P1→P2；P3 与 P4 在 P2 之后可分别推进，P4 所需外设先按接口独立仿真。P5 需 P1—P4 集成，P6 的告警状态机可在 P4 后开发，最终需与 P5 回归；P7 汇总全部。阶段按依赖推进，不设置工期。

## 16. 已确认与未确认

- 已确认方向：完整数字标牌方案、静态图片、640×480 基线、源码+镜像+资源+工具+文档交付；按依赖推进。
- 未确认采购：编码器/红外、调试 DAC。编码器占 J1 三根 GPIO，红外单独占一根；DAC 若同时使用必须另分配引脚并增加 I2S 发送器。
- 未验证：板上显示、音频、资源、时序、性能；检查表勾选与测试记录一致才算完成。
