# 06 OSD与字体

版本v1.1，2026-10-18。字库地址、配置表与完整菜单以02 §3.2、§6为准。

## 1. 图层与时间对齐

顺序：图像/转场→图像颜色调整→HUD L1→菜单/告警/提示L0。L0覆盖L1，菜单打开时可以隐藏HUD避免遮挡。RGB及HS/VS/DE/x/y在相同流水级数后输出。

字形为0/1掩码，不做字体抗锯齿；面板另有固定alpha：HUD背景1/2黑、菜单背景3/4黑，使用移位加，不能将“文字二值”误写成所有OSD都不透明。前景为白色/高亮蓝，告警红白，颜色常量在RTL与黄金模型一致。

## 2. 字库和编码

| 类型 | 格式 | 存储 |
|---|---|---|
| ASCII | 96字符，每字8×16，16 B | 内嵌ROM，1536 B |
| 中文/符号区位槽 | 94×94，每槽16×16，32 B | W25Q64，起点0x010000 |

中文每行2字节，MSB在左；地址公式见02，整区282752 B。GB2312的6763汉字填入对应槽，未分配码位填零；没有单独索引表。GB2312标题为双字节，非法码位输出替代字形；文件路径仍为ASCII，不暗示FAT32支持中文LFN。

解码器输出16位文字单元：bit15=0时低7位ASCII；bit15=1时低14位为区位槽索引0—8835。文本存储在取得缓存结果后，将中文单元改为 `0x8000 | slot9`，低9位为缓存槽0—399，不能再按GB2312槽号解释。位置、颜色和层由行描述符保存；当前没有逐字符倍宽。双bank每bank两层、每层12条×40单元，共1920×16bit，低于40列×30行/层的设计上限。

## 3. 字形缓存与预取

当前实现为400槽×32 B=12.5 KiB字形缓存，逐槽查询，缺字按CLOCK二次机会规则替换，跳过locked和实时pinned槽。固定菜单共111个唯一中文字符，锁定上限默认192槽；动态标题只pin实际引用，不占固定锁定预算。没有可替换槽或锁定超预算时返回错误，不等待视频停顿。

每槽17位元数据（reference、locked、valid、14位GB2312槽号）存入独立双端口RAM。复位后用400拍清表，完成前不接受get，行读返回缺字框；字形数据RAM不复位。查询及替换通过请求读、元数据判断和决策拍完成，替换候选提前译码，但pin保护在决策沿仍取实时输入。同地址元数据读写用写前valid旁路，避免依赖跨端口冲突时的RAM输出。

视频行缓冲已实现两行、两层，每像素保存ink及2位颜色，共640×2×2×3bit=960 B。渲染器先寄存行描述符再判断覆盖范围；ASCII单元先寄存字符再读取组合ROM，中文单元使用缓存的一拍同步行读。增加的准备拍需要完整光栅测试确认供行期限。

50 MHz单线SPI读取完整32 B字形仅数据就5.12 μs，另有命令/地址开销。每行水平消隐6.4 μs无法覆盖一整行多个冷缺字；**不能保证所有Flash取字都在同一消隐完成**。在菜单/标题提交前完成所需字形预取，双缓冲文本描述；仍缺字时显示替代字符并计GLYPH_MISS，不停视频。首帧/告警只依赖已缓存字符与ASCII。

Flash设置写期间依赖锁定字模，不发必须实时完成的Flash取字请求。运行替换字体是可选工具功能，若实现需版本/CRC和缓存失效握手；当前正式字体来源为Flash镜像与ASCII ROM。

## 4. 菜单、HUD与提示

菜单五组：播放、显示、音频、系统、关于，全部参数与范围只定义在02 §6.2。面板400×320居中，超出内容滚动；先保证条目、焦点与读回正确，再添加100 ms光标和200 ms提示动画。

HUD建议宽192、高112，右上角距边8px，含：

```text
FPS  59.5
BW   44%  GRANT xx%
VUND 0    AUND 0
RD   2.71MB/s
ITEM 03/12
```

示意值仅是排版示例。FPS按VS计数，BW按设备实际忙周期，GRANT按授予周期，SD按真实收到字节；VIDEO_UND/AUDIO_UND分别统计。运行时长、卡容量、固件版本可在自检/关于页显示。

LUT/FF/BRAM来自构建报告并随固件元数据写入，标注BUILD，不冒充实时硬件测量。音画仅显示计划偏移与内部事件差；外部测量结果注明测量条件。

底部提示条高32px，淡入200 ms、停2 s、淡出200 ms。缩略图文件名在单元内保留区，不超出213×160；页码与选择高亮为OSD，不强制重绘原图。

## 5. 自检页

显示器件/固件、SD初始化/吞吐、FAT32项数、SDRAM测试状态、HDMI时序、VIDEO_UND/AUDIO_UND。只有实际执行过的检查才写OK；未检测写UNKNOWN/NOT TESTED。HDMI核锁定不等于显示器已经发声。

资源占用、供电、芯片温度没有相应传感器就不显示动态读数；需要测温时在测试报告记录仪器。外接设备不存在不应阻塞主系统。

## 6. 验证与资源

ASCII ROM1.5 KiB、中文字形缓存12.5 KiB、双bank文本单元3.75 KiB、两层彩色双行缓冲960 B；缓存元数据、描述符、pin及快照另计。不可简单把这些相加当作物理BRAM占用，综合后还须登记块类型、深度/位宽配置、LUT及FF。

2026-10-25实现调整：字形行RAM和文本单元RAM均采用独立的同步读出寄存器，缺字框/空白回退在寄存器之后选择，保持原有一拍读延迟。RAM内容不复位，是否有效由缓存valid和文本描述符限定。TD已能将两者识别为BRAM；最终物理块数、普通警告及模块资源结果见 [综合检查记录](../record/2026-10-25-P0-TD综合检查.md)。这不代表整机资源或硬件读取已通过。

验证所有GB2312合法汉字与生成工具位图/CRC一致；界面抽样和分页看图用于人工确认方向/位置。无效码位、ASCII边界、缓存冲突、多冷缺字、Flash忙及文本更新跨域应由相应自检覆盖，实际执行结果以验证记录为准。字体数据校验通过不等于“6763字在缓存里同时常驻”。


标题快照使用`osd_title_snapshot`：将9×40 B标题顺序复制到360×8-bit双时钟RAM，仅590bit元数据与32bit标题发布序号留在跨域邮箱。应用端每次替换完整标题/长度时同沿更新不回绕序号；复制期间若序号变化则全部重试，不发布混合标题。RAM写入完成后才提出跨域请求，源端必须等真实文本结果的ack返回后才能覆盖；字体端按一拍同步读接口逐行读取40 B，再执行原有GB2312裁剪和发送。共同复位只使快照失效，不清RAM；停钟不能释放在途所有权。完整协议见02的OSD资源优化接口说明。

本次只消除OSD邮箱中的宽标题寄存器；应用暂存/前台两份标题仍保留。`tb_osd_menu_builder`已准备RAM逐字节比较、复制中途更版、非法地址、边界发布、停钟、共同复位和三种builder输入模式的测试；`tb_player_layout`检查标题发布序号的原子性。本版尚未运行这些测试或重新综合，旧报告不能证明新RAM推断、资源容量、跨域时序或供行期限通过。
