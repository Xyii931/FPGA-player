## 1. 两条路径

```text
装载：TF → FAT32 → BMP → 缩放 → 旋转/版式写入 → 离屏SDRAM槽
显示：SDRAM按源行预取 → 双源行缓存 → 行内映射/权重 → 混合 → OSD → HDMI
```

常态缩放、旋转、版式在写路径完成。转场滑动/推挤在行缓存内平移，中心缩放按映射源行预取；**扫描时序是纯光栅，源坐标不必恒等**。不在SDRAM端逐像素随机取数。

每个槽固定640×480 RGBA，读锁/READY及generation见02。新画面全部准备完成后在帧边界提交；重绘时保持旧帧，禁止故意插黑。

### 2.1 坐标约定

采用半像素中心映射：`s=(d+0.5)*src/dst−0.5`，边界钳位到`[0,src−1]`。最近邻取`floor(s+0.5)`；双线性取floor及相邻点、权重为小数部分。RTL使用16.16定点，除法在任务开始时计算，累加器逐像素推进。黄金模型必须采用相同的定点截断/舍入，不能用库默认算法直接判逐位一致。

RTL的具体截断为`step=floor((src<<16)/dst)`、`origin=(step>>1)−32768`、`s_q16=origin+d*step`；底行先从`d=dst−1`开始减step，不从底边重新定义舍入。双线性使用16位小数、水平不提前舍入、最终加`2^31`再右移32；RGBA四通道同规则。输出两种行序均须保持归一坐标，不能将底行先流写成y递增。任务成功还要消费下采样不用的全部源尾行；若BMP尾字节在缩放成功后失败，上层仍须废弃候选槽。当前实现四拍发起邻点同步读、一拍归集、四拍逐通道运算并允许反压，实际RAM映射、乘法资源及125 MHz时序待TD验证。

双线性每次保留相邻两完整源行，最大1920×32×2=15 KiB；处理底行先时使用对应两行及坐标，不要求倒序整帧。水平方向可串行计算，吞吐随硬件并行度测量；三通道四邻点不能仅计为四次8×8乘法。

黑边由离屏槽预清屏保证；写入器只覆盖有效矩形。1920×1080原图从TF载入可超过2秒，预取要尽早进行，迟到保持旧帧。

## 3. 旋转与等比适配

先确定旋转后的宽高：0/180为W×H，90/270为H×W，再按目标矩形等比适配。可先将输入缩到`pre_w×pre_h`，再旋转写入：

| 方向 | 写入坐标，不含居中偏移 |
|---|---|
| 0 | `(u,v)` |
| 90顺时针 | `(pre_h−1−v,u)` |
| 180 | `(pre_w−1−u,pre_h−1−v)` |
| 270顺时针 | `(v,pre_w−1−u)` |

640×480转90度时：先等比缩到480×360，再转为360×480，最后加偏移`(140,0)`。所有结果必须落在目标矩形；不可用原画布常数639/479处理已经缩放后的坐标。

RTL `image_geometry`先对旋转后源宽高比较交叉积，受限轴取目标矩形尺寸，另一轴取整数floor并钳至少1；居中余量向下取整，奇数余量留右/下。`image_rotate`以预旋转宽高执行上表并加有效矩形偏移，只增加一个弹性像素寄存器，不重排输出顺序。`image_transform`等待下游接受几何后才同时启动唯一scaler和rotate，分别消费它们的真实终态；旋转完成较早时仍等缩放器消费跳过的源尾行，错误时退休同伴的内部abort不覆盖根因。组合成功也不能代替文件尾部检查或writer退休，黑边仍由writer清屏。独立几何/旋转及组合自检脚本见`src/sim/MEDIA.md`，未经编译或执行。

转置写入会降低SDRAM行命中率。P2测量；若不能满足后台写入预算，采用小块转置缓存/分块写，而不是宣称随机写成本可忽略。

## 4. 七种转场

令`W=640,H=480`，t为0—65536的17位进度，表中公式用归一化`t∈[0,1]`表达，RTL映射为定点。t=0必须完全等于A，t=1完全等于B。所有效果共用RGB混合器，但地址映射与权重生成可分别实现。

| 效果 | 像素规则 |
|---|---|
| fade | A/B同坐标，B权重=t |
| slide（B从右滑入） | d=round(W*t)；x≥W−d时取B(x−(W−d),y)，其余取A(x,y) |
| push（向左推） | x<W−d时取A(x+d,y)，其余取B(x−(W−d),y) |
| wipe（斜擦） | q=x*H+y*W；阈值=round(2*W*H*t)，阈值内用B；端点显式覆盖 |
| blinds | 条带宽32；偶条局部x=x mod32，奇条反向；局部x<round(32*t)用B |
| mosaic（块状切换） | 8×8块，rank8=低8位的确定性坐标散列；阈值round(256*t)，rank8小于阈值用B |
| zoom（B中心放大） | 中心矩形尺寸round(W*t)×round(H*t)，矩形内映射到B整帧，外部取A；t=0时矩形为空 |

表中slide的“其余取A”是覆盖式滑入；push同时移动旧图。除fade外默认边界为硬选择，16像素软边实现时需明确仅在两源合法重叠区混合。

mosaic固定散列：`rank8=((bx*37) XOR (by*73)) & 255`，bx=x>>3、by=y>>3；可用移位加常数乘，不需块排名ROM。rank可重复，表示部分块同时切换。这个效果定义为块状揭示，不宣称图像降采样马赛克。

slide/push用行缓存随机读x，SDRAM仍完整读取对应源行。zoom为目标每行预取映射的B源行，行内按最近邻映射；t小会跳过源行、t大可复用源行。只需两源行缓冲，但必须测行截止时间，不能把zoom当成纯权重变化。

边界软混合宽度统一16像素，可作为效果参数的固定实现；两源边界坐标必须合法，出画布源填背景/关权重。端点不残留软边。缓动可使用小ROM的smoothstep，资源及位宽计入报告，不能用“零成本”描述。


实现准备（2026-10-23，未验证）：`transition_plan`、`transition_map`、`blend_unit`已落盘，接口见02 §5.12.1。plan按一次valid/ready命令保存effect/progress/epoch/tag，done及全部计划字段保持至接受；非法effect/progress返回error1，调用方不得安装失败计划。map与blend各固定两级、每拍一像素、无像素反压，HS/VS/DE、坐标、帧/行起点与身份同路对齐。测试使用由源坐标生成的RGB代替行RAM，直接连接时为四级；真实reader同步读延迟及其旁路控制还须在scanout中一起加入。

## 6. 颜色与OSD

保留亮度、对比度与饱和度，顺序为对比度→饱和度→亮度→OSD，参数在帧边界锁存。每像素三个通道并行/流水，不能因多级处理降低启动间隔。

- 对比度k∈[−4,4]、默认0：每通道`c1=clamp(floor(((c−128)*(8+k)+4)/8)+128,0,255)`。
- 灰度`Y=(77*R1+150*G1+29*B1+128)>>8`，常数乘可移位加；饱和度s∈[0,16]、默认8：`c2=clamp(floor(((c1−Y)*s+4)/8)+Y,0,255)`。s=0为灰度、s=8原色、s=16增强。
- 亮度b∈[−4,4]、默认0：`c3=clamp(c2+16*b,0,255)`。

负数除法的floor与有符号算术右移对应，黄金模型使用同一舍入规则。宽中间值避免溢出；资源和视频时序在P2/P4综合回填，不以“动态LUT重算”省略乘法成本。随机效果从本节七种中选择，不能计作第八种独立图像算法。

OSD按06叠加，HS/VS/DE/x/y通过同样流水级数；不要只延迟RGB。缺行时输出上一完整缓存行并记VIDEO_UND，不能宣称它等于冻结整个上一帧。
