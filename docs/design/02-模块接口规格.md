# 02 模块接口规格

版本 v1.1，2026-10-18。本文是常量、布局、协议和模块契约的唯一规范来源。状态为**接口设计基线**；接口表定义必需信号和语义，编写 RTL 时应形成完整 Verilog 声明并审查，不再声称可以跳过 IP 文档直接实现所有底层时序。

## 0. 编码与事务约定

| 项目 | 规定 |
|---|---|
| RTL | Verilog-2001；小写下划线模块名，I_/O_/IO_ 端口，S_ 内部，参数全大写 |
| 复位 | 内部高有效，每个目标域异步置位、同步释放 |
| FSM | `localparam` 命名；编码由综合结果选择，不预先禁止 one-hot |
| 数据流 | valid/ready：上升沿二者同时为 1 才传输；等待时载荷稳定；last 仅随有效传输 |
| 命令 | req/ready 采用相同握手，done/err 返回一次，事务带 tag；取消也必须返回终态 |
| 跨域 | 异步 FIFO 或稳定载荷+toggle/ack；事件使用握手，不能直接传单拍脉冲 |
| 位宽 | 字节、字、像素、采样帧均明确；算术中间位宽显式扩展、饱和处理 |
| 乘法 | 常数可移位加；动态系数按并行度/时序综合评估，预算不依赖 DSP |
| 测试 | 每个功能模块有自检仿真；结构模块可由集成仿真覆盖 |
| 变更 | 先更新契约及相关专题，再改 RTL；IP 经验值不得冒充规格 |

目录组织保留 `src/rtl/{top,storage,media,display,ui,common}`、`src/ip`、`src/constraints`、`src/sim`，PC 工具放 `tools/`。加密核通过端口/参数复用，不修改加密内容。

## 2. 时钟、复位、顶层与约束

### 2.1 时钟

| 信号 | 频率 | 来源 |
|---|---|---|
| `clk_50m` | 50 MHz | R7 |
| `sd_card_clk` | 100 MHz | sys PLL C0 |
| `ext_mem_clk` | 125 MHz | sys PLL C1 |
| `ext_mem_clk_sft` | 125 MHz，预期180° | sys PLL C2，按 SDRAM IP 实际要求核对 |
| `video_clk` | 25 MHz | video PLL C0 |
| `hdmi_5x_clk` | 125 MHz | video PLL C1，与 video_clk 固定5:1 |

只用两个 PLL；同一 PLL 的输出频率不能用一行共同倍频系数描述，应逐输出设置并核对报告。125 MHz 串行器时钟不是 ACR 的 TMDS 时钟。失锁行为由分域复位处理。

### 2.2 复位契约

`reset_gen` 必须接入 `I_clk_50m/I_clk_100m/I_clk_125m/I_clk_25m`、两个 PLL lock、KEY1 长按和媒体复位请求，并分别输出 sys(100M)、mem(125M)、media(125M)、sd_media(100M)、video(25M) 复位。没有目标时钟端口就无法实现目标域同步释放。

| 输出 | 异步置位原因 |
|---|---|
| sys / mem | 上电保持、全局复位、sys PLL 失锁 |
| video | 上电保持、全局复位、video PLL 失锁 |
| media / sd_media | 上述相应基础复位，或经过隔离的媒体软复位 |

**媒体请求不得进入 video/mem/sys 基础复位**。SDRAM 仲裁、前台行缓存与 HDMI 保持运行。媒体复位流程：屏蔽新媒体事务→排空已提交请求→撤销后台槽写锁/文件上下文→复位媒体模块→重初始化。超时则报错并保持旧帧，不把未完成返回误投给新事务。

上电保持计数在 50 MHz 域，`2^20` 拍约20.97 ms；计数器须用器件/工具支持的上电初值或复位原语，P0 验证。各域两级以上同步释放，全局按键复位允许 HDMI 中断。PLL 失锁后不等待已停止时钟发出同步事件才置位。

### 2.3 顶层引脚基线

| 端口 | 引脚 | 方向/注意 |
|---|---|---|
| I_clk_50m | R7 | 时钟输入 |
| I_key[0:3] | A2/B2/B1/C1 | 低有效；分别KEY1—KEY4 |
| I_sw[0:3] | C8/C7/C6/C5 | 拨码 |
| O_led[0:3] | A4/A3/C10/B12 | 输出 |
| O_buzzer | H11 | 低有效，另检查SW5硬件使能 |
| I_uart_rx / O_uart_tx | F12/D12 | UART |
| O_sd_ncs/dclk/mosi，I_sd_miso | A12/A14/A13，B14 | TF SPI |
| O_flash_cs_n/sclk/mosi，I_flash_miso | P8/M9/P7，N8 | W25Q64；WP=P9、HOLD=R9按原理图确认保持高的方式 |
| O_hdmi_clk_p/d0_p/d1_p/d2_p | C3/G5/F1/E1 | 使用厂商差分PHY；配对负脚C2/G6/F2/D1由PHY与约束处理 |
| O_hdmi_scl / IO_hdmi_sda / I_hdmi_hpd | P2/R2/J6 | DDC开漏/上拉及HPD按板卡电路核对 |
| I_enc_a/b/sw | J13/F13/L14 | 扩展三输入，3.3V；接线方向可配置 |
| I_ir | J12 | 独立扩展输入；连接器针号需对照手册，不沿用未核对的J2-31标注 |

编码器和 IR 为可选接口；未接时有确定的空闲电平。PHY 使用参考 IP 要求的 LVDS33 配置，不能仅凭一个 `_p` 输出自行假定自动得到正确的差分信号。DDC 上拉是否已在板上存在不能只凭源码下结论。**本表是引脚分配基线，不是已通过的完整 ADC 文件**；P0 逐脚核对，尤其 WP/HOLD、扩展口和 DDC。

### 2.4 时序约束

1. 为50 MHz输入建立主时钟；为实际PLL输出建立或由工具推导生成时钟，包括存储移相输出，核对频率、相位及实例匹配。
2. `video_clk` 与 `hdmi_5x_clk` 同源、有真实通路，不声明互斥。
3. sys PLL 的100/125 MHz输出保持真实关系分析；接口即使使用异步FIFO，也不能无审查地切断整个时钟域。
4. 不同PLL域的FIFO/握手按厂商建议约束，包含同步器、格雷指针的最大延迟/偏斜要求。不存在同步结构的路径不能靠false path豁免。
5. SPI以实际SCLK输出边沿、卡/Flash的tCO、板延迟建立min/max IO约束；删除未经器件时序推导的固定8ns/4ns模板。
6. PHY内部与TMDS输出按厂商时序模型分析，不用`O_hdmi_*`通配符同时豁免DDC等控制信号。
7. 保存clocks、setup/hold、未约束路径和exceptions报告。P0形成可运行SDC，未完成前不得勾选“时序通过”。

## 3. 存储规范

### 3.1 SDRAM 帧槽

所有地址为21位**32-bit字地址**。`addr=base+y*640+x`。

| 槽 | 首地址 | 尾地址 | 用途 |
|---|---|---|---|
| SLOT0 | 0x000000 | 0x04AFFF | 当前/转场源/合成槽，角色动态分配 |
| SLOT1 | 0x04B000 | 0x095FFF | 同上 |
| SLOT2 | 0x096000 | 0x0E0FFF | 预取/离屏 |
| SLOT3 | 0x0E1000 | 0x12BFFF | 预取/合成临时 |
| SLOT4 | 0x12C000 | 0x176FFF | 单页缩略图 |
| SLOT5 | 0x177000 | 0x1C1FFF | 常驻告警/安全帧 |
| 保留 | 0x1C2000 | 0x1FFFFF | 未分配；分配前登记 |

像素为 `{R[7:0],G[7:0],B[7:0],A[7:0]}`。导入BMP时A统一255；内部合成若使用alpha须显式说明直通/预乘，当前选**非预乘**。扫描显示背景帧时取高24位RGB。

每槽元数据含state(FREE/LOADING/READY/READ_LOCK/ERROR)、素材标识、版式参数、generation。只有READY可以在帧边界加读锁提交，读取中的槽不得覆盖。释放需等行读取事务排空。

### 3.2 W25Q64 唯一分区（字节地址）

| 首地址 | 尾地址 | 内容 |
|---|---|---|
| 0x000000 | 0x000FFF | 设置A，4 KiB |
| 0x001000 | 0x001FFF | 设置B，4 KiB |
| 0x002000 | 0x00FFFF | 保留，不放索引表 |
| 0x010000 | 0x05507F | 字库：94×94×32=282752 B，包含空码位 |
| 0x055080 | 0x05FFFF | 对齐保留 |
| 0x060000 | 0x06FFFF | 开机Logo，自定义RGBA RLE，最多64 KiB |
| 0x070000 | 0x0FFFFF | 保留 |
| 0x100000 | 0x7FFFFF | 内置演示素材包，最多7 MiB |

字库地址=`0x010000+((hi−0xA1)*94+(lo−0xA1))*32`，两个字节均在A1—FE，否则替换字符。空码位填零；6763为GB2312汉字数量，不是区位槽数量。不再使用会跨入字库区的4 B/字索引表。

设置记录：magic=`CFG1`，version(u16)=1、payload_len(u16)=128、sequence(u32)、payload(64×u16 LE)、CRC32(u32)。CRC覆盖magic至payload，采用CRC-32/ISO-HDLC（poly 0x04C11DB7，反射实现0xEDB88320，init/xorout 0xFFFFFFFF）。末尾commit(u32)=0才有效，擦除态FFFFFFFF无效。写非当前副本→读回验证→最后编程commit，始终保留旧有效副本。启动选择序号最新的有效记录，序号比较按模2^32半区间规则。

Logo RLE：16 B头，magic=`RLE1`，width(u16)、height(u16)、payload_bytes(u32)、CRC32(u32，覆盖RLE载荷)；记录为run(u16，1—65535)+RGBA(u32)，均小端，按画布光栅展开。必须恰好W×H像素，越界/长度/CRC错误拒绝；不宣称任意图片都能压到64 KiB。

演示包：16 B头，magic=`DEM1`、version(u16)=1、count(u16)、table_bytes(u32)=count×20、table_crc32(u32)；每项20 B：type(u16，1=RLE1图、2=标准WAV)、id(u16)、offset(u32)、size(u32)、crc32(u32)、reserved(u32)=0。offset相对0x100000，不能落在头/表内，条目不能重叠或越界。id将图片与音频关联；同一type/id不可重复，同id的不同type可配对。所有CRC均采用CFG1相同的CRC-32/ISO-HDLC，条目CRC覆盖该条目完整文件字节；无对应音频则静音。包用于自带有限演示，不替代TF的≥4张BMP验收。

### 3.3 SDRAM 底层适配与仲裁

已核实：`SD/sdram.v`包装`sdr_as_ram`，实例化`EG_PHY_SDRAM_2M_32`，`self_refresh_open=1`、`App_ref_req=0`；公开接口包含初始化、刷新/忙状态、写使能/地址/掩码/数据、读使能/地址及返回有效/数据。原语内部加密。

**公开端口和参考用法不足以证明每周期接收、固定一拍返回、busy可忽略或10拍是IP硬要求。** 参考`frame_fifo_read.v`确实在发完请求后等待10拍；这只能作为基线实验依据。P0必须测试初始化、读写连续/随机、刷新、读写切换、掩码和多请求返回次序。

底层适配层提供`cmd_valid/ready、wr、addr[20:0]、wdata[31:0]、wmask[3:0]、tag`与`rvalid、rdata[31:0]、tag、err`。命令仅在确认底层可以接受时ready；读响应由**实际Sdr_rd_en**触发，使用按序tag队列路由，不能由固定延迟计数伪造。若IP不能证明多请求接收，先限制单事务，再按实测扩展；满足显示带宽前不进入P2出口。

仲裁器六个客户端，类别分三档，**不称六级QoS**：

| idx | 客户端 | 优先级 |
|---|---|---|
| 0/1 | A/B行预取 | 扫描截止时间优先，两路按最早截止 |
| 2 | 图片解码写入 | 后台 |
| 3 | 版式合成源读取 | 后台 |
| 4 | 版式合成目标写入/清屏 | 后台 |
| 5 | 自检/保留 | 最低 |

客户端使用上述事务握手。突发最多32字，在**已验证安全边界**切换；不要求每拍重选。扫描将欠载时优先，后台用轮转与年龄防饥饿，但后台强制授予不能突破扫描截止。音频FIFO在BRAM、从TF供数，**不占本仲裁器的“音频客户端”**；其优先级由扇区调度器实现。

BW是观测窗口内设备实际忙周期/总周期；授予率另记，二者不能混称。双源显示146.3 MB/s为有效数据需求，不能把500 MB/s原始峰值当保证持续性能。

## 4. 文件、播放列表和音频格式

### 4.1 TF 路径与目录

```text
/PLAY/PLAYLIST.TXT
/PLAY/IMG/*.BMP
/PLAY/AUD/*.WAV 或 *.APT
```

FAT32只读，512 B扇区；支持MBR或裸卷、非连续簇、8.3名与ASCII LFN。大小写不敏感。至少3个独立打开上下文：image、audio_A、audio_B；每个含文件大小/位置/簇链状态。目录及列表扫描在播放前或受调度的后台阶段进行，不破坏在播上下文。最多64项、路径64字节；LFN非ASCII则只以合法8.3别名访问。

### 4.2 PLAYLIST.TXT 唯一语法

```ini
[GLOBAL]
interval = 10
transition = fade
transition_ms = 400
order = name
[ITEM]
file = IMG/01.BMP
audio = AUD/01.WAV
title = SPRING
duration = 8
transition = push
transition_ms = 600
```

| 键 | 范围/缺省 |
|---|---|
| GLOBAL interval | 1—600整数秒，默认10 |
| GLOBAL transition | fade/slide/push/wipe/blinds/mosaic/zoom/random，默认fade |
| GLOBAL transition_ms | 200/400/600/1000，默认400 |
| GLOBAL order | name/list/random；显式列表默认list，无列表默认name |
| GLOBAL bgm | 可缺省，背景音轨路径；ITEM没有audio时使用，均未指定则静音 |
| ITEM file | 必填，相对`/PLAY`或绝对路径，≤64 ASCII字节 |
| ITEM audio | 可缺省，未设置时继承GLOBAL bgm，bgm也未设置则静音；路径规则同上 |
| ITEM title | ASCII或GB2312，≤40字节且不拆双字节字符；工具负责UTF-8转换 |
| ITEM duration/transition/transition_ms | 可缺省，继承GLOBAL对应值 |

行缓冲256 B，最大有效行255 B；忽略首尾空白，只有首个非空字符为`#`才是注释。不支持行尾注释、引号转义、目录穿越`..`。节与键不区分大小写，title内容保留。未知键记录告警后跳过，数字越界/格式非法使用对应缺省并记错；同键最后一次有效值生效。无file的ITEM丢弃；素材打不开跳过。列表缺失/没有有效项则枚举`/PLAY/IMG`，失败再枚举根目录；按名排序。

### 4.3 BMP

BM，DIB size=40，planes=1，compression=BI_RGB(0)，bpp=24/32；宽1—1920，高绝对值1—1080且不为0。检查pixel_offset、行跨度、乘加溢出和文件长度；`row_bytes=((width*bpp+31)>>5)<<2`。BMP字节BGR/BGRA重组为RGBA，**A统一255**；本版本不从BI_RGB高字节推断透明度。正高为底行先，解析器输出坐标归一为顶行为0，但不承诺到达顺序是从上到下。

### 4.4 WAV 与 PCM 幅度

RIFF/WAVE，fmt的format=1、channels=2、rate=48000、bits=16、block_align=4；非fmt/data块按长度及偶数字节填充跳过。data长度为4的倍数，不能超过文件边界。

PCM16转换：`sample24={sample16,8'b0}`；16-bit的−32768/32767变为24-bit的−8388608/8388352，保持相对满幅幅度。仅符号扩展虽然保持整数值，却比满幅24-bit低约48.16 dB。所有混合使用带符号扩展的宽中间值，末端饱和到24-bit，不回卷。

### 4.5 APT0（自定义，版本由magic定义）

| 偏移 | 字段 | 类型/值 |
|---|---|---|
| 0x00 | magic | 4 B `APT0` |
| 0x04 | sample_rate | u32=48000 |
| 0x08 | channels | u16=2 |
| 0x0A | format | u16=1（IMA 4-bit） |
| 0x0C | block_align | u16=1024，总块字节数 |
| 0x0E | header_bytes | u16=24 |
| 0x10 | total_frames | u32，每声道有效样本数 |
| 0x14 | reserved | u32=0 |

字段小端，不再使用相互重叠的16 B头。每块左声道512 B后右声道512 B；每声道4 B头（predictor s16、step_index u8、reserved=0）+508 B数据。每数据字节先低nibble后高nibble；头predictor是首样本，块含每声道1017样本。末块填充到1024 B，按total_frames截断，文件长度应为24+ceil(total_frames/1017)×1024。

IMA公式：`diff=step>>3`，按code的bit0/1/2分别加step>>2、step>>1、step，bit3取负；predictor相加饱和到s16，index按{-1,-1,-1,-1,2,4,6,8}更新并钳位0—88。使用标准89项step表；每nibble只加一次基础`step>>3`。解出的s16同PCM左移8位。此布局是自定义APT，PC编码器与RTL必须使用同一规范。

## 5. 主要模块契约

本节的信号组必须在模块声明中体现；跨域桥可独立实例化。端口名遵循I_/O_方向，不再保留方向名相反的`input O_gnt`或`output I_cmd_ready`。所有返回均含err和事务tag，具体tag位宽在连线时统一，至少能区分上下文与在途请求。

### 5.1 pll_tree / reset_gen / clk_monitor

`pll_tree`输入50 MHz，输出2.1全部时钟及两个lock。`reset_gen`按2.2实现。`clk_monitor`每域自由计数器转格雷码后同步到50 MHz，观察1 ms窗口差分；禁止直接在50 MHz采样100/125 MHz单拍边沿。必须有复位/clear输入与丢钟锁存状态，lock独立用于快速失锁保护。

### 5.2 sd_spi_phy

100 MHz；输入cmd_valid/ready、idx[5:0]、arg[31:0]、crc[7:0]，输出rsp_valid及足够的R1/R3/R7/R2字节、err；数据输出byte_valid/ready、byte[7:0]、block_last、crc_ok。接口支持CMD0/8/55/41/58/16/17/18/12/13，读模式不承诺CMD25写卡。暂停SCLK只在允许的字节边界，包含有界超时；CMD12用原事务内的控制子状态处理，不先随意抬CS结束多块读。

SCLK除数为**完整周期拍数**：初始化250（400 kHz），工作4（25 MHz）。初始化至少1 s时间预算轮询ACMD41，不用16次快速轮询代替1 s等待。SDSC需CMD16设512 B，并对旧卡CMD8不支持分支作兼容或报告不支持。

### 5.3 sd_sector_reader

100 MHz；请求`valid/ready,lba[31:0],count[7:0],context,tag,priority`，count=0非法、1—128有效；返回`byte_valid/ready,data[7:0],sector_last,request_last,context,tag,err`。请求队列4项。音频水位紧急请求在扇区/安全多块终止边界优先，限制图片连续块数量，测最大阻塞；不能等128块完整传输后才调度音频。

初始化、card_present、timeout/CRC错误、取消完成均显式输出。CMD13探测仅在总线空闲、安全边界每500 ms发起，无卡重试间隔2 s。

### 5.4 fat32_core

125 MHz，至少3个独立文件上下文。输入open(valid/ready,ctx,path流,len)、read(valid/ready,ctx,offset,length)、close/cancel；输出open_done(size,err)、read字节流(valid/ready,ctx,offset,last,err)。read允许带offset以支持暂停恢复，内部可缓存簇检查点，无需声称随机定位恒定时间。

目录接口dir_open与entry流(valid/ready、name字节流及len、size、attr、first_cluster、last、err)，路径/名最多64字节，不用24位信号冒充8字符名。扇区请求与数据返回使用5.3完整接口，跨域异步FIFO，**不能只有请求端口没有数据输入**。目录上下文与音轨上下文分别保存；FAT/扇区缓存按context/tag匹配。

### 5.5 media_indexer

125 MHz；输入scan_start、目录/文件流及配置缺省；输出busy/done/degraded/err与item写入流。item记录必须含图片/音频路径引用、标题引用、duration、transition、transition_ms、合法标志，item_count为7位可表示64。字符串存BRAM/受管理存储，不把64字节路径硬塞进128位端口。扫描中不覆盖正在播放的索引，完成后原子提交generation。

### 5.6 flash_ctrl / settings_store

100 MHz；flash请求含op(READ/PROGRAM/ERASE)、addr[23:0]、len、tag，具备写入valid/ready字节流、读取valid/ready字节流及done/err/busy。包含物理CS/SCLK/MOSI/MISO；WP/HOLD按板卡电路接法处理。页编程不跨256 B页，擦除4 KiB，轮询BUSY有超时。

settings输入cfg_write(addr[5:0],value[15:0])、save与load；输出查询读地址/数据、load_done/save_done/busy/err。连接flash事务口，不能遗漏擦除、长度和返回数据。仅显式保存落盘，写期间使用缓存字模，Flash控制器忙不阻塞整个100 MHz时钟域。

### 5.7 bmp_parser

125 MHz；start(file_size)与输入byte_valid/ready；输出header_valid/ready（width,height,bottom_up,pixel_offset,row_bytes）和pixel_valid/ready（RGBA,x,y,last）及done/err。非法文件整项拒绝；检查planes/尺寸/跨度/文件长度。等待时输入和输出均可反压，不丢字节。坐标归一但到达可逆序，下游不能假定y递增。

### 5.8 image_scaler

125 MHz；start(src_w/h,dst_w/h,algorithm,orientation)、源像素valid/ready/x/y与目标像素valid/ready/x/y，done/err。计算目标尺寸/边框后开始，支持任意规定尺寸的最近邻/双线性。双线性保留相邻完整源行，最大1920像素×32 bit×2=15 KiB；输出到目标区域，黑边由writer清屏保证。不能用640深缓存声称保存1920宽原始两行。

每个像素四邻点、RGB三个通道；若只用一个8×8乘法器，时序要覆盖所有通道乘加，不能直接承诺4周期/像素。吞吐由实现报告，反压保证正确。底行先的源按归一化y计算输出，不要求把整幅原图先存BRAM。

### 5.9 fb_writer

125 MHz；命令valid/ready含job(CLEAR/LOAD/COMPOSE/ROTATE)、dst_slot、源槽/文件引用、矩形、方向、素材generation；像素流valid/ready；存储读写事务均完整接入；返回done/err。需读改写或源合成时使用仲裁客户端3/4，不把只有写口的模块描述成能自行完成多源合成。

job开始先取得独占写锁；清屏→分区域累积写入→校验完整→READY。旋转在写入地址映射完成，见04；不允许越界。多窗口源不足则调度重读，不能覆盖READ_LOCK槽。

### 5.10 fb_reader

125 MHz预取+25 MHz读口。输入行任务valid/ready（source,base,src_y,generation,deadline,line_tag）；输出line_ready/err及匹配tag，通过握手跨域。每源2×640×32双口行缓存，视频端输入bank/x读取RGBA。已有源行可重复复用，缩放转场的不同src_y需真正重取。

返回使用适配层rvalid，不假定固定延迟。预取下一行，帧开始前准备首行；行缓存换bank需双方确认，不允许同bank边写边读。generation防止切槽后晚返回覆盖新行。

### 5.11 scanout_engine

25 MHz；输入帧边界提交的A/B槽、effect、duration_frames、progress、ready；输出HS/VS/DE/x/y及转场坐标请求和权重。向reader发下一行任务，输出缓存bank/x_A/x_B；接收两路像素有效，流水线延迟统一对齐HS/VS/DE/x/y。

源行来自行任务，行内平移在缓存读地址完成；缩放按04计算src_y。HS/VS极性遵循视频转AXIS与HDMI核契约，P0核对，不能据命名断言核自动取反。欠载使用上一个完整缓存行作为降级并记VIDEO_UND，不覆盖为正在填充的半行；保持时序，出口要求零欠载。

### 5.12 blend_unit

25 MHz；每拍接受A/B RGB及weight[16:0]（0—65536）、valid/DE/坐标，固定延迟输出RGB及对齐控制。每通道`(a*(65536−w)+b*w+32768)>>16`，中间至少25位无符号，输出钳位。要求启动间隔1拍；三通道并行流水，不能用“每级处理一个通道”得到颜色来自不同像素。若降为8-bit权重须更新契约与黄金模型。

### 5.13 audio_decoder / samp_tick / acr_gen

audio_decoder在125 MHz，两个独立ctx，输入start/seek/stop与带ctx的字节valid/ready，输出ctx、L24/R24、sample_index、valid/ready、eof/err。APT按块缓存独立左右声道后输出成对样本，需计入额外缓存；可用通用FIFO预算或另计，不能遗漏。PCM与APT均按4.4归一化。

samp_tick在25 MHz持续运行；33位相加取进位，ACC保留低32位。只由video复位清零，暂停/换图不改变它；静音仍持续给HDMI有效采样。

acr_gen在25 MHz；默认N=6144、CTS=25000，每48个samp_tick输出一次acr_valid（约1 kHz），N/CTS在该拍有效；保留参考测量模式用于对照，首次完整测量窗口后才有效。125000不作为合法缺省试验档。见05。

### 5.14 audio_mix（通用新增模块）

25 MHz；两路FIFO的valid/ready、L/R、sample_index，音量0—16、mute、fade参数、提示音；输出L/R24、sample_valid、PLAYED位置、AUDIO_UND与水位事件。各路增益0—65536，总和≤65536；交叉淡化`g_A=1−t,g_B=t`，混提示音需预留增益或饱和。见05暂停、欠载与时间线规则。

### 5.15 ui_core / menu_engine / osd_compositor

ui_core在100 MHz，原始按键/拨码/编码器/IR先同步，按键20 ms消抖、KEY1 3 s长按；输出事件valid/ready及载荷，队列8项，溢出报告。KEY1复位事件需独立可靠通路，不能被满队列丢弃。编码器正交状态校验+基于时间的消抖，不把4拍40 ns当机械消抖充分条件。

menu_engine在25 MHz，输入跨域事件队列与配置读回/当前模式，输出配置事务、文本写口、菜单可见/焦点。不能只写参数而无读回，导致菜单与UART显示不一致。

osd_compositor在25 MHz，输入RGB和对齐HS/VS/DE/x/y；字符/图形描述写口跨域握手，输出同延迟RGB与控制。字体端口含req_valid/ready、byte_addr[23:0]、rsp_valid/ready与字节数据，缓存命中/缺字状态。完整字库地址超过17位，不再用17位BYTE地址。菜单/告警L0优先于HUD L1；半透明面板是独立矩形层，字形为二值掩码。字形预取不得阻塞视频。

### 5.16 playlist_scheduler

125 MHz；输入事件、索引表读回、配置、帧计数/音频played时间戳、装载done/err及buffer水位；输出prefetch、槽锁/释放、音轨start/stop/seek、帧提交命令（effect,duration,anchor）、状态与计时。提交经完整载荷握手到video域，在垂直消隐边界锁存后返回ack。

当前项稳定进入后尽早预取下一项，不等80%停留时间。显示时长自目标转场完成起计；准备未完成则保持当前画面并记迟到。单项音频长于停留时长按切换淡出，短于停留则到EOF后静音；本版不自动循环单项音轨。背景bgm到EOF后预打开同文件的新上下文并交叉淡化循环，继续遵循最多两轨同时活动。暂停停止播放时间线、保持当前画面，已开始转场先完成再暂停。

转场中NEXT/PREV：以最后待执行目标为基准更新索引，合并为一个待目标；转场结束且目标已准备后再开始，不替换在用源。ALERT优先，可在下一帧边界终止当前转场，硬切到常驻告警；退出恢复保存的播放项、剩余停留时间与音轨sample_index，必要时重载/定位并预充。稳定播放时保存准确断点；若告警发生在转场中，进度<0.5保存来源项，否则保存目标项，同时保存所选项的音轨位置；返回时呈现所选项的完整画面，不重建半途中混合图像。

告警书签还保存播放模式、素材generation、音轨路径/格式和配置快照；所选音轨尚未开始时位置为0。若媒体已更换，按文件身份重新校验，无法恢复时明确提示并回到首个有效项。连续告警更新同一告警内容/期限，不覆盖首次插播前的正常播放书签。

### 5.17 telemetry_uart / watchdog / app_top

UART在100 MHz，115200 8N1，除数868；接收256 B行缓冲，最大255 B，CR/LF/CRLF只结束一行。超时200 ms丢弃半行并报ERR。输出结构化命令valid/ready与完整文本/参数流，输入应答和遥测流；不能用单个32-bit arg承载任意告警文字。

watchdog在125 MHz，输入reset、enable(active事务)、kick(progress)、timeout_budget；输出timeout与来源。默认5 s，不监视正常空闲状态；卡命令自身超时独立处理。

app_top只连接模块、分发事件与模式优先级：ALERT > MENU > THUMB > PLAY > SELFTEST。不得把媒体读取、像素运算塞进顶层。告警退出/超时明确恢复，菜单可在前台而播放调度暂停；具体状态转换有仿真覆盖。

## 6. 交互、配置与菜单

### 6.1 按键与拨码

KEY1短按PREV、KEY2 NEXT、KEY3 AUTO开关、KEY4 MENU/返回；菜单内分别上一项、下一项、确认、返回。KEY1长按3秒全局复位，长按不再补发短按事件。

SW1 AUTO、SW2 MUTE、SW3 PiP/FULL、SW4 DEMO。启动从保存配置加载，再由拨码初值产生对应事件；SW1/SW3之后仅在变化时更新运行配置，按键/菜单/UART也能改变它们。SW2=1持续强制静音，SW4=1持续进入演示，不能被UART取消，返回普通模式需拨回。告警优先级高于DEMO，静音覆盖告警音。

配置同拍冲突按硬覆盖→告警控制→板载/扩展UI→UART处理；普通配置进入单一事件队列按顺序更新。运行配置、实际生效值（含覆盖）分别可查询。Flash只在SAVE时保存基础运行配置，不保存临时告警/硬覆盖状态。

### 6.3 UART 唯一命令

命令/键不区分大小写；空格分隔，字符串参数为余下整行，不支持`SET key=value`。

| 命令 | 参数/行为 |
|---|---|
| PING | PONG |
| VER | 固件版本、git-sha |
| STAT | 模式、帧率、读速率、BW、VIDEO_UND、AUDIO_UND、item、实际配置 |
| NEXT / PREV | 切换请求 |
| PLAY [n] | 0起始项号；无n则继续放映 |
| PAUSE / RESUME | 暂停/继续时间线与音频；AUTO是否轮播另由配置控制 |
| MODE PLAY/THUMB/MENU/SELFTEST | 普通模式请求；强制DEMO/告警可能使请求延后或拒绝 |
| SET key value / GET key | 修改/查询基础配置与实际生效值 |
| SAVE / DEFAULT | 显式保存 / 恢复运行默认 |
| SCAN | 请求重扫，忙时ERR busy，不能破坏在播上下文 |
| ALERT sec text | sec=1—600，text为GB2312/ASCII≤40 B；常驻背景+OSD文字 |
