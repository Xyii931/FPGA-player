# 存储链仿真排查记录

> 历史排查记录，配置和结论可能已过时；当前情况以[项目状况](当前项目状况.md)及源码为准。

本文记录 2026-11 针对"主工程上板后 MOUNT/SCAN 阶段卡死"的仿真排查过程与结论。

## 结论摘要

已覆盖的存储链场景曾在仿真中通过，不能由此断定 RTL 或板级实现不存在其他问题。实际读卡故障尚待复现和定位。

| 验证项 | 参数 | 结果 |
|---|---|---|
| `async_fifo` 单测 | DATA_BITS=61, ADDR_BITS=3, 83.33/100 MHz, 24 条 | ✅ 无丢失 |
| 连续扇区读 | `fat32_sector_port → sd_storage` 双时钟, 20 次 | ✅ 20/20, error=0 |
| 连续扇区读 + 卡 busy | 卡模型在 token 前插入 200 字节 0xFF, 10 次 | ✅ 10/10, error=0 |
| `fat32_mount` 集成 | 与主工程一致的接线 | ✅ 返回结果（卡模型数据非 FAT32，报 error=3 属预期） |
| `lean_media_source` 全链路 | mount 阶段 | ✅ 正常 MOUNT → RETIRE → RETRY |
| `lean_media_source` 全链路 + FAT32 镜像 | 64 MB 稀疏镜像、4 个目录项、50 字节 busy | ✅ `catalog_err=0`，`count=4` |

## 关键结论

最后一项把卡模型换成了"合法 FAT32 卷 + 真实卡 busy"，media source 完整走完
MOUNT → SCAN → ONLINE，正确识别出 4 张图片。该结果只覆盖当时的模型及测试条件。
后续检查发现，挂载阶段的本地超时可能在已接受的扇区请求结束前退出，导致结果无人接收；现已修复并增加相应测试。

## 排查中确认的测试台缺陷（重要）

这些缺陷一度造成"卡在第 6 个扇区"的误判，记录如下避免重复踩坑：

1. **超时判断失效**：`wait (st == 3'd3 || $time > 50000000)` 只在 `st` 变化时求值。
   20 次读约需 210 ms（400 kHz），50 ms 的超时导致打印落在第 6 次请求刚发出的瞬间，
   看起来像"卡死"。正确做法是用独立的 `initial #delay` 或每个时钟沿检查时间。

2. **起始握手门控**：mount 的 `I_start_valid` 不能在 `card_ready` 之前拉高后又被撤销，
   否则 mount 永远停在 IDLE。

3. **端口地址接线**：`fat32_sector_port.I_lba` 必须接请求方自己的地址寄存器，
   不能误接成端口的 `O_lba`（会变成高阻 `z`）。

## 复现用例

测试台位于 `.tmp_sim/`（临时目录，未纳入版本管理）：

- `tb_cmd_fifo.v` —— 命令 FIFO 单测
- `tb_seq_reads.v` —— 连续 N 次扇区读（双时钟 + 卡模型，可配 `BUSY_BYTES`）
- `tb_mount_chain.v` —— mount 集成测试
- `tb_media_chain.v` —— media source 全链路测试

卡模型 `src/sim/models/sd_spi_card_model.v` 新增参数：

```verilog
parameter integer BUSY_BYTES = 0   // token 前插入的空字节数，模拟真实卡 busy
```

编译与运行示例：

```powershell
vlib work
vlog -work work src/rtl/common/reset_sync.v src/rtl/common/async_fifo.v `
     src/rtl/storage/*.v src/sim/models/sd_spi_card_model.v .tmp_sim/tb_seq_reads.v
vsim -c -novopt -do "run -all; quit -f" work.tb_seq_reads
```

## 尚未覆盖

`lean_media_source` 的端口仲裁在**大量连续读**（根目录扫描阶段）下的行为尚未仿真。
补齐需要给卡模型提供合法的 FAT32 磁盘镜像（引导扇区 + FAT 表 + 根目录项），
使 media source 能真正进入扫描并连续发起数十次扇区读。

## 硬件侧待查

若仿真补齐后仍然全部通过，则问题应在真实卡或板级：

1. 真实卡在 CMD17 后的 busy 时长可能远超模型；
2. 真实卡对时钟停止/片选时序的容忍度；
3. 16.67 MHz 读时钟下的信号完整性（但 400 kHz 下同样失败，此项可能性较低）；
4. 建议用逻辑分析仪抓一次扫描阶段的 SPI 波形，对比 mount 阶段。
