## 二、关键结论

### 2.1 HDMI 显示（已解决）

**根因**：`video_*_axis` 源端把 `valid` 一直拉高、并按 `ready` 节流，导致 HDMI IP 的
`line_space` / `frame_space` 相位匹配失败，显示器进入"无信号/白屏"状态。

**修复**：`scanout_axis_bridge.v` 改为本地生成 800×525 光栅，

- `valid` 只在 640 有效区内拉高（按 DE 门控）；
- 行/场消隐长度等于 `HTOTAL`/`VTOTAL`，满足 IP 的相位匹配；
- 忽略 `I_ready`（IP 只在 `last` 后短暂拉低 ready）。

验证：`p0_hdmi_raster_20261031.bit` 彩条正常显示。

### 2.2 SD 读卡（关键线索已找到，未完全解决）

**最重要的发现**：把 SD 域时钟从 **100 MHz（PLL）** 换成 **50 MHz（板载晶振 `I_clk_50m`）** 后，
一次 512 字节扇区读**成功完成**（探针显示 `G3` = 收到字节 + 收到 done）。

在此之前，SD 域跑 100 MHz 时读**永远不完成**（`S2/G0`：port 停在 RECEIVE，一个字节都没回来）。

**结论**：SD 域跑 100 MHz 时读卡失败；50 MHz 下正常。原因可能是 100 MHz 域的时序余量、
时钟质量，或 SPI 采样路径在该频率下的建立/保持不足（仿真无法复现）。

**当前卡点**：mount 现在报 **error 4 = 找不到分区**（`E4`），即已经在解析 MBR，但没识别到分区项。
真实卡为 **7.40 GB FAT32 主分区**（已确认）。正在用 `O_dbg_type` 探针观察 MBR 分区表类型码。

## 五、构建流程与注意事项

### 5.1 构建命令

```powershell
$env:FPGA_PLAYER_PROJECT='lean_player'
$env:FPGA_PLAYER_MODULE=''
$env:FPGA_PLAYER_PLACE_ROUTE='1'
$env:FPGA_PLAYER_SEED='5'          # 见下方"seed"
$env:FPGA_PLAYER_ROUTE_MULTITRY='1'
$tcl=((Resolve-Path 'src/td_project/synthesize.tcl').Path -replace '\\','/')
cd .local/td-build/lean_player/<时间戳>
& 'D:/TD_6.2.1/bin/td_commands_prompt.exe' $tcl
```

生成 bit（TD 图形界面可能未安装或不便使用时的脚本流程）：

```tcl
import_device eagle_s20.db -package EG4S20BG256
open_project <proj>.al -single_run
load_run_param -run phy_1
import_db <run>/<proj>_pr.db
bitgen -bit <proj>.bit
```

### 5.2 必须满足的条件

- **时序必须为正**：查看 `*_phy.ts` 的 `SWNS` / `HWNS`，两者都要 ≥ 0；
- 常见失败：`PHY-8023`（增量布线冲突）、`RUN-8102`（资源/策略）、`PHY-1030`（hold 修复回退）；
- 同一份代码在不同 seed 下结果差异很大，需换 seed 重试（常用的 1/2/3/4/5）。

### 5.3 已知坑

1. **BOM**：PowerShell 的 `Set-Content -Encoding UTF8` 会写 BOM，ModelSim 报
   `non-printable character 0xef`。写入后需用 `[System.IO.File]::WriteAllBytes` 去掉前 3 字节。
2. **`.al` 被 TD 重写**：手工追加的文件条目可能被丢弃，导致"黑盒"错误。
   新增 RTL 文件时务必确认 `.al` 里的 `CompileOrder` 连续。
3. **Tcl 路径**：`td_commands_prompt.exe` 的脚本参数必须用**正斜杠**，反斜杠会被吞掉。
4. **构建耗时**：主工程约 12–15 分钟/轮，p0 约 1.5–3 分钟/轮。
5. **时序余量极小**：主工程长期在 ±0.1 ns 附近，任何逻辑增加都可能打破平衡。

卡模型 `src/sim/models/sd_spi_card_model.v` 新增：

```verilog
parameter integer BUSY_BYTES   = 0;  // token 前插入的空字节，模拟真实卡 busy
parameter integer IMAGE_FAT32  = 0;  // 使用内置稀疏 FAT32 镜像（MBR + LBA2048 引导扇区）
```

运行方式：

```powershell
vlib work
vlog -work work src/rtl/common/reset_sync.v src/rtl/common/async_fifo.v `
     src/rtl/storage/*.v src/sim/models/sd_spi_card_model.v .tmp_sim/tb_scan_chain.v
vsim -c -novopt -do "run -all; quit -f" work.tb_scan_chain
```

**重要教训**：本轮的"卡在第 6 个扇区"是测试台超时判断写错造成的误判
（`wait(... || $time > 50000000)` 只在 `st` 变化时求值）。写测试台时务必用独立的
`initial #delay` 或每个时钟沿检查时间。详见 `docs/存储链仿真排查.md`。

### 7.1 待解决：mount 报 error 4（找不到分区）

现状：

- 真实卡：7.40 GB，FAT32，主分区；
- mount 读到签名 55AA（否则报 3），但分区表扫描没有识别到 0x0B/0x0C 项；
- 已加探针 `O_dbg_type`，最新 bit 显示"四个分区项中第一个非零类型码"。

建议下一步：

1. 用 `lean_player_ptype2_20261101.bit` 观察 `XX`：
   - `0C`/`0B` → 扫描逻辑问题，检查 `fat32_mount.v` 第 171–185 行的候选选择；
   - `00` → MBR 数据没读对，回到读通路；
2. 若卡是 **superfloppy**（无 MBR）或 **GPT**，需要扩展 mount：
   - superfloppy：`IDENTIFY` 分支已支持（BPS=512 时直接 `VALIDATE`）；
   - GPT：需识别 0xEE 并读 GPT 头，工作量较大；
3. 也可先用 PC 确认分区起始 LBA 与类型码，便于比对。
